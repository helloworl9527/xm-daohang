# 个人收藏系统视觉重设计方案

## 0. 目标与边界

目标是让系统从“能用的链接列表”变成安静、快速、可扫描的个人知识入口：公开端优先发现和检索，管理端优先批量处理和维护。

本方案只改变信息组织、视觉层级和交互表现，不要求替换 Next.js、React、Lucide、next-intl 或现有 API。公开目录仍只展示 `web/github`，`doc` 继续保留在收藏库和语义问答中。现有 CSS class 可以分阶段迁移，避免一次性重写 2234 行全局样式。

## 1. 视觉方向

### 方向 A（推荐）：Ink & Signal，暖白底的编辑型工具

- **基调**：暖白/石墨文字、深墨色导航，极少量珊瑚橙作为“可操作/已选中”信号。内容密度中高，边界靠留白和细线，而不是大量卡片阴影。
- **色彩**：背景 `#F6F5F2`，主表面 `#FFFFFF`，文字 `#17181A`，次级文字 `#686A70`，结构线 `#E4E2DC`，强调 `#E4573D`，成功 `#2E7D5B`，警告 `#B7791F`，错误 `#C53D3D`。
- **字体**：优先系统字体栈 `-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`；中文不加载远程字体，标题使用 600 权重、正文 400。大标题紧凑，正文行高 1.55，字距保持 0。
- **适合原因**：收藏系统的核心是长期阅读和找回，不应像营销站抢夺注意力。暖白降低长时间阅读疲劳，墨色侧栏提供稳定定位，珊瑚色只标记真正需要行动的地方。公开端有“出版物/目录”感，后台仍像可靠的工作台。

### 方向 B：Midnight Workshop，深色技术工作台

- **基调**：深石墨背景、分层灰表面、青绿色强调，适合夜间整理和代码仓库浏览。公开端与后台均使用深色，重点依靠高对比标题和等宽元数据。
- **色彩**：背景 `#111315`，表面 `#1A1D20`，浮层 `#23272B`，文字 `#F2F0EA`，次级文字 `#9DA5A8`，结构线 `#343A3E`，强调 `#62D5B0`，链接 `#7DB7FF`。
- **字体**：系统无衬线为正文，URL、类型、状态、数量使用 `ui-monospace, SFMono-Regular, Menlo, monospace`。
- **适合原因**：GitHub 和 AI 检索是重要内容，深色能强化“工作台”气质；但长期阅读、中文对比度、浅色环境可读性和打印体验成本更高。

**建议先实现方向 A，并保留主题变量。** 不做完整主题切换；变量命名允许未来增加深色主题，避免组件直接写死颜色。

## 2. 公开端 `/` 信息架构

### 2.1 页面层级

1. 顶部工具栏：品牌、分类快速跳转、语言切换、管理入口。
2. 首屏操作区：一句明确标题 + 一个合并检索入口。关键词搜索是默认路径，AI 问答是同一输入框旁的显式切换。
3. 分类索引：桌面端左侧 sticky 索引，移动端横向滚动标签；显示分类名和数量。
4. 内容区：按分类分组的站点卡片；搜索提交后替换为结果视图，并保留“清除搜索”。
5. AI 回答区：不抢首屏焦点，放在检索区下方成为可展开工作区；展示回答、引用来源和当前额度/不可用状态。

### 2.3 搜索与 AI 问答

- 保留一个明确的主输入框，避免两个看起来相同的表单。输入框右侧使用分段控件 `[搜索] [问答]`；默认是搜索，模式切换不清空输入。
- 搜索：回车或按钮提交到现有 `POST /search`，结果区显示匹配数、查询词和清除按钮。结果顺序仍由服务端决定。
- 问答：提交到现有 `POST /ask`；回答区展示回答正文、引用的站点卡片和“未找到相关内容/服务未就绪/额度已用尽”状态。引用卡片沿用站点卡片组件，增加 `cited` 标记。
- 问答不可用时，控件仍可见但置为 disabled，并在同一行显示具体原因；不要隐藏入口造成能力不确定。

### 2.4 分类与内容卡片

- 分类不使用堆叠大卡片；使用带数量的文本索引，减少视觉噪声。当前分类滚动时使用 `aria-current` 和珊瑚色短指示线。
- **网页卡片**：favicon/站点首字母、标题、2 行摘要、标签、域名和外链图标。点击整卡打开原网址，新窗口并保留 `noopener`。
- **GitHub 卡片**：使用仓库图标/首字母、`owner/repo`、README 摘要、语言/更新时间或 stars 等已有字段；不要伪造未存储的 stars。类型徽标明确写 `GitHub`。
- **文档**：不放入公开目录；在后台用文档类型徽标、文件 URL/标题和处理状态呈现。
- 卡片统一最小高度和固定摘要行数，避免加载或长标题导致网格跳动。桌面 3 列，平板 2 列，手机 1 列。

### 2.5 空、加载和错误状态

- **空目录**：显示“还没有已完成的公开站点”，提供管理入口；不要放大型插画。
- **空分类**：保留分类标题和计数，正文显示轻量文本“此分类暂时为空”。
- **搜索无结果**：复述查询词，给出“清除搜索”和“尝试标签/域名”两个动作；不擅自调用 AI。
- **加载**：使用与真实卡片相同尺寸的 3 个骨架行/块，只使用 opacity 变化；保留分类索引位置。
- **错误/不可用**：在内容区显示可重试的状态条，错误信息不移动输入框；问答的上游错误与搜索错误分开表达。

## 3. 管理后台布局

### 3.1 框架与导航

桌面为 240px 固定侧栏 + 可滚动内容区；移动端侧栏变为顶部栏和抽屉。侧栏分三组，当前页有珊瑚色边线和浅色底：

```text
收藏库
  添加收藏
  全部收藏
整理
  分类工作台
系统
  模型与嵌入
  运行设置
底部：语言切换 · 退出登录 · worker 状态
```

`/admin` 继续重定向/复用“添加收藏”，但导航明确标为“添加收藏”，避免出现无意义的“首页”。

### 3.2 后台线框

```text
┌──────────────┬──────────────────────────────────────────────────────┐
│ CZ 收藏库     │ 收藏库 / 全部收藏                         [添加收藏] │
│              ├──────────────────────────────────────────────────────┤
│ 添加收藏      │ 页面标题 + 说明                                      │
│ 全部收藏      │ ┌关键词────────┐ ┌标签────────┐ ┌状态────┐ [筛选] │
│ 分类工作台    │ └──────────────┘ └────────────┘ └────────┘ [清除] │
│ 模型与嵌入    │                                                      │
│ 运行设置      │ 48 条收藏 · 最近更新                                  │
│              │ ┌──────────────────────────────────────────────────┐ │

│ worker 在线   │ │   github.com/...  摘要…     #标签 #标签  更新日期 │ │
│              │ └──────────────────────────────────────────────────┘ │
└──────────────┴──────────────────────────────────────────────────────┘
```

### 3.3 library 列表

- 默认使用“紧凑行卡片”而非表格：每行是可点击详情入口，左侧类型图标，中心是标题/URL/摘要，右侧是状态、标签、更新时间和更多操作。
- 桌面可以在 900px 以上切换为 2 列密度视图，但不改变 API 分页；移动端强制单列。
- 状态采用文本 + 颜色 + 图标三重表达：`processing` 时钟、`completed` 勾、`failed` 警告；不可只依赖颜色。
- 筛选区域保持现有 `q/tags/status/cursor/limit` 契约；排序和游标继续由服务端控制。加载更多按钮固定在列表尾部，避免自动无限滚动遮挡键盘用户。
- 详情页采用“主内容 + 元数据侧栏”：标题、原链接、摘要编辑、标签和分类为主列；处理状态、来源、时间、重抓/删除为侧栏动作。破坏性删除保留确认对话框。

### 3.4 添加/编辑表单

- 添加页首屏只有 URL 输入和明确的“加入收藏”按钮；支持 web、GitHub、doc 的类型提示在输入后显示，不要求用户手选类型。
- 处理流程在提交后显示为时间线：已接收 → 抓取 → 摘要/标签 → 向量/分类 → 完成/失败。沿用已有异步 worker，不在前端假造进度百分比。
- 编辑页把人工摘要开关、标签、分类放在内容主列；模型设置、来源和重抓放在元数据区。自动分类字段显示“AI 分类”或“手动保护”，避免误覆盖。
- 表单错误就地显示在字段下方；成功后使用轻量状态条，并保留返回列表的路径。

## 4. 设计系统基础规范

### 4.1 CSS 变量（方向 A）

```css

  --color-accent-hover: #c94732;
  --color-accent-soft: #fbe8e3;
  --color-success: #2e7d5b;
  --color-warning: #b7791f;
  --color-danger: #c53d3d;
  --color-focus: #1669d3;
  --font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
  --font-mono: ui-monospace, SFMono-Regular, Menlo, monospace;

  --shadow-float: 0 12px 30px rgb(23 24 26 / 10%);
  --shadow-focus: 0 0 0 3px rgb(22 105 211 / 28%);

```

### 4.2 尺度与表面

- 间距只使用上述 4px 基数；页面外边距 `--space-6`，区块间距 `--space-7`，卡片内边距 `--space-4`。
- 普通卡片最多 `--radius-md`，输入和按钮 8px；标签使用 pill。页面大区块不包成浮动卡，避免“卡片套卡片”。
- 默认无阴影；只有悬浮菜单、对话框和 sticky 工具栏使用 `--shadow-float`。结构面用边线和背景色区分。
- 公开端最大内容宽度 1200px，后台内容区最大 1280px；阅读正文限制 68ch。

### 4.3 交互状态

- `hover`：背景提升一档、外链图标轻微右移 2px；不改变布局尺寸。
- `active/pressed`：按钮和卡片即时缩放到 `0.98` 或变更表面色；反馈发生在 pointer-down。
- `selected`：使用 `--color-accent-soft`、左侧 2px 强调线和 `aria-current`，不能只靠颜色。
- `disabled`：降低对比度并禁止 pointer；仍显示原因文本，不使用不可读的 `opacity < .55`。
- `focus-visible`：统一 `--shadow-focus`，不移除浏览器焦点轮廓；键盘路径与鼠标路径等价。
- 动效仅用于 opacity/transform，默认 critically damped、约 0.2–0.4s；尊重 `prefers-reduced-motion: reduce`，改为无位移淡入。透明材质在 `prefers-reduced-transparency: reduce` 下改为实色表面。
- 点击区域至少 40px 高，移动端主要按钮至少 44px；图标按钮提供 Lucide 图标和可见 tooltip/`aria-label`。

## 5. 对现有实现的影响分级

- **低风险（纯视觉）**：`globals.css`、公开卡片/索引 class、后台侧栏与列表 class、Lucide 图标尺寸、骨架和状态样式。路由与 API 不变。
- **中风险（组件结构）**：将搜索和问答包成一个模式切换容器；把列表行拆为类型徽标/主信息/元数据三列；移动端侧栏抽屉。保持现有 fetch DTO 和 URL 参数。
- **高风险（需单独确认）**：引入公开端新的排序/“近期添加”导航、让 doc 出现在公开目录、增加 GitHub stars/语言等数据库未存字段、改变问答检索阈值或分页协议。这些会修改服务 SQL、接口或数据模型，不属于本次视觉重设计默认范围。

## 6. 评审结论

建议用户确认方向 A（Ink & Signal）后，按“公开首页 → 后台壳与 library → 详情/表单 → 设置与分类工作台”的顺序实施。第一阶段只替换视觉 tokens 和布局骨架，保留现有数据契约；每阶段用 Playwright 覆盖桌面 1440px、平板 1024px、移动 390px，并检查中英文、键盘焦点、空/加载/错误状态。
