# 收藏系统 · 导航站增强 UI 规范

> 状态：**UI 已批准；方向 C「工作台」为最终界面方向**。  
> 里程碑：M2 导航站增强；需求事实源：`.workflow/requirements-nav-enhancement.md` v0.6（F206 显示文案修订）。  
> 原型：`.workflow/ui-prototype-nav-enhancement/`；数据、AI 建议、进度和保存反馈均明确属于原型演示。

## 1. 选定方向与设计目标

### 1.1 选定方向

- 正式方向：C「工作台」。A「索引侧轨」和 B「流式目录」只保留在原型控制器中用于比较，不进入正式实现规范。
- 设计主题：高密度、可维护、快速全局扫描；在延续 M1 克制编辑感的基础上，让数百条目录仍能高效浏览。
- 公开端目标用户：熟悉收藏库、希望快速找站点或直接向收藏库提问的访客。
- 公开端唯一任务：在同一页按分类或字面关键词找到站点，同时明确区分“找站点”和“向 AI 提问”。
- 管理端目标用户：单管理员。
- 管理端唯一任务：安全地维护固定分类和条目单一主分类，AI 只提议、管理员决定是否应用。

### 1.2 共同视觉语言

- 命名色值：Mist `#F5F7F4`（页面底）、Paper `#FFFFFF`（交互表面）、Ink `#17211D`（正文/深色分类索引）、Search `#087F6C`（主要动作/锚点）、Source `#265FAF`（改名/来源语义）、Signal `#D15A3C`（风险/失败/原型提示）。
- 字体角色：`Inter / PingFang SC / system-ui` 用于正文、控件和数据；`Songti SC / Georgia / ui-serif` 用于页面与分类标题；`ui-monospace` 用于编号、计数、进度和变更类型。
- 材质：顶部栏、分类索引层、底部 AI 问答框使用有限的半透明材质；不在卡片内重复玻璃效果。`prefers-reduced-transparency` 下改为实色。
- 形状：卡片和控件圆角 5–7px；状态标签可用胶囊形；禁止装饰性渐变、无意义大色块和多层嵌套卡片。
- 图标：命令使用 Lucide；站点优先展示真实 favicon，失败时回退同尺寸域名首字母，不允许破图或布局跳动。
- 国际化：所有新增 UI 文案进入 next-intl 中英文资源；AI 站点总结、AI 分类建议和问答答案保持中文。

## 2. 公开首页信息架构

页面顺序：

1. 品牌栏与语言切换。
2. “目录”标题行：左侧仅显示标题“目录”，右侧为紧凑 **F209 关键词搜索输入框与提交按钮**；不显示 eyebrow、副标题、搜索标签或说明小字。
3. 常规目录或关键词结果：二者使用同一内容位置，避免同时出现两套长列表。
4. 固定于底部安全区的 **F207 AI 问答框**，输入、提交、来源提示和额度保持现状。

首页**不展示** hero 大标题/宣传语，也**不展示**“今日轮换”或每日 3 条卡片，且**不再有顶部整块搜索区**。M1 `dailySelections` 后端逻辑不在本次 UI 范围内拆除，只是不再从公开首页呈现。

首页自上而下严格分为：目录标题行（含右对齐紧凑关键词框）→ 主体导航目录/关键词结果 → 底部 AI 问答框。关键词结果出现时标题行搜索框和底部 AI 问答仍在，常规分类长列表暂时替换为结果列表；清空后恢复。

## 3. F209 关键词找站点

### 3.1 与 AI 问答的辨识

- 桌面端关键词框右对齐于显示标题“目录”的标题行，与标题平行；占用原“原型演示数据”标签位置，不形成独立大区块。
- 紧凑组件视觉上只保留搜索输入框、清空按钮和提交按钮；移除“关键词找站点”标签与“字面匹配 · web / GitHub · 不使用 AI”说明。输入框、搜索区域和图标按钮仍分别保留中英文 `aria-label`，不能因精简文案失去可访问名称。
- 移动端在同一标题区内落到标题下方，输入框保持完整宽度，提交按钮至少 `44×44px`；不使用会隐藏输入内容的图标展开模式。
- AI 问答框不上移、不与关键词框并排；继续固定在底部原位，保留“AI 问答”标记、输入占位“向收藏库提问…”、提交行为、来源边界“回答仅来自收藏库 · 最多 10 条来源”和额度。
- 两个输入框的名称、空间位置、图标、动作和结果形式都不同：目录标题行关键词返回卡片；底部 AI 问答返回中文答案与来源。

### 3.2 提交与结果呈现

- 采用显式提交（按钮或 Enter），不在每次键入时请求后端；输入中仅显示清空按钮和边界说明。
- 正式实现应把非空关键词同步到 URL 查询参数（建议 `q`），以支持刷新、复制链接和浏览器前进/后退；清空参数恢复常规目录。
- 匹配范围固定为 `status=completed` 且 `type in (web, github)`；匹配字段为标题、AI 中文总结和标签；不含 doc、不做向量/语义检索、不生成 AI 内容。
- 结果区**替换常规分类目录的列表主体**，搜索框保持可见；结果复用导航卡片样式，不按分类分组。
- 结果标题显示关键词、命中数和“不调用 AI”；清空关键词后恢复分类索引、空分类和未分类末尾规则。
- 关键词为空不发请求；输入边界与过长/非法字符错误以内联文本显示，焦点留在关键词框。

### 3.3 状态

- 默认：空输入 + 常规分类目录。
- 输入中：输入值、清空按钮、提交提示；常规目录继续可见，尚未请求。
- 加载：结果位置显示 3 个卡片骨架和 `aria-busy=true`；搜索框保持输入值；不使用人工延迟。
- 有结果：标题“关键词结果”、命中数、字面匹配说明、卡片列表和“清空关键词”。
- 空结果：标题“没有匹配的站点”，说明标题/总结/标签均未匹配且未调用 AI；提供清空动作。
- 失败：结果位置显示具体错误与重试；不把失败误写为无匹配，底部 AI 问答仍可用。

## 4. 导航目录

- 分类索引：C 方向在桌面使用全宽深色六栏索引；平板变为 3 列；移动端横向滚动。点击后滚动到分组并把键盘焦点移至目标，设置 `aria-current="location"`。
- 分组顺序按固定排序；“未分类”永远最后并公开；空分类显示标题、`00 SITES` 和虚线空提示。
- 组内站点按名称排序；桌面 3 列、平板 2 列、移动 1 列。
- 卡片：favicon/回退图标、标题、AI 中文总结（视觉最多两行）、标签和外链图标；整卡为 `<a target="_blank" rel="noopener nofollow">`。
- 目录加载：原位骨架；空库说明 web/GitHub 完成后出现且 doc 不进入；失败使用 `role=alert` 和重试，并明确关键词框与 AI 问答仍保留。

## 5. 管理端 F202 分类建议工作流

### 5.1 动作入口

管理端分类页首区不再表现为一次性初始化，而是长期存在两个并列动作：

- **F202a 补充建议**：低风险入口，只允许 AI 建议新增分类；不出现改名、合并或删除类型。
- **F202b 全量重拟**：高影响入口，可建议新增、改名、合并和删除；使用更强的风险边界说明，但不使用恐吓式文案。
- 入口旁持续显示“AI 建议不会直接覆盖分类”和“人工分类始终保护”；可显示最近一次应用时间、模式、接受/忽略数用于追溯。

### 5.2 生成与 diff 预览

- 触发后在原位进入生成状态；AI 失败不改变既有分类，并保留手动 CRUD。
- AI 返回临时 diff 后才显示预览，尚未写库；可“放弃预览”。
- diff 类型用文字 + 色彩双重表达：新增（绿）、改名（蓝）、合并（琥珀）、删除（红）。
- 每条显示：类型、原分类、建议目标/新名称、自动/人工条目数量、接受/忽略按钮。
- 已接受项允许编辑新名称或目标；忽略后字段禁用但保留上下文，可再次接受。
- 合并/删除项必须选择其下**自动分类条目**的去向：合并目标或未分类。
- 预览顶部固定显示保护横幅：`category_manual=true` 条目数量和“不会被改动”；人工条目不参与自动迁移或重跑。
- F202a 预览只可能包含“新增”；若无候选显示无建议状态且不生成空 diff。

### 5.3 应用确认

- 主按钮显示当前已接受数量；全部忽略时禁用应用。
- 点击后打开二次确认，汇总“应用 N / 忽略 M / 人工保护 K”及合并/删除迁移策略。
- 二次确认提供默认开启但可关闭的复选项：“应用后对自动归类的存量条目按新类目重跑”。
- 复选项必须明确只处理 `category_manual=false`，不会触碰人工分类。
- 返回预览不丢失编辑；确认后才开始写入。应用按钮在请求开始后禁用，避免重复提交。

### 5.4 进度与结果

- 应用中：显示分类变更进度、自动条目重跑进度和人工保护说明；后台任务不可伪装为可取消，用户离开页面后再次进入应能恢复服务端真实状态。
- 成功：显示新增/改名/合并/删除/忽略数量、人工保护数量、重跑条目数和进入未分类数。
- 部分失败或失败：显示服务端真实已应用/失败项目及下一步动作，不以成功 toast 掩盖；允许回到 diff 或按服务器支持重试。
- 应用结果和模式（F202a/F202b）应进入可追溯记录；界面不伪造历史数据。

## 6. 现有分类 CRUD 与条目归属

- 分类新增/重命名：内联唯一性校验；失败时保留输入并聚焦错误。
- 删除：系统“未分类”不可删除/改名；其他分类二次确认，文案明确其下 N 条内容转未分类。
- 条目分类选择器：单一主分类；人工选择后显示“人工分类已保存，后续 AI 不覆盖”。请求期间只禁用当前选择器；失败恢复原值并给内联错误。
- 目录概况：固定分类、已归类、未分类、人工分类保护、排除的 doc 数；数字用等宽/tabular 字形。

## 7. 交互物理与反馈

- 按下在 `pointer-down` 立即反馈，卡片/按钮缩放至约 `0.985`；松开从当前显示值恢复，不锁住输入。
- 分类锚点滚动、toast 和面板切换均可被新输入打断；Reduced Motion 下禁用平滑滚动与位移动画。
- 搜索提交、AI 建议生成和应用进度不使用为了展示而设置的人工延迟；原型延迟必须标注为演示。
- toast 只用于轻量确认；搜索失败、AI 失败、diff 应用结果必须在工作区持久呈现，并配 `aria-live` 或 `role=alert/status`。
- 破坏性分类删除使用模态确认；F202 应用使用独立确认模态，不能复用含糊的“确定？”文案。

## 8. 响应式与无障碍

- 验证尺寸：桌面 `1440×1000`、移动 `390×844`；使用 Grid/Flex 和 `minmax(0,1fr)`，禁止页面级横向溢出。
- 触控目标至少 `44×44px`；长分类名、标题、域名和 diff 目标必须换行或截断，不能撑破容器。
- C 方向管理端桌面为 `74px + 工作区` 图标侧栏，所有隐藏文字的链接有 `aria-label`；移动端恢复带文字的顶部横向导航。
- diff 桌面三列（类型 / 变更 / 决策），移动端变为两列并把接受/忽略按钮移到整行；迁移策略选择器改为单列。
- 页面提供跳到主要内容链接；标题层级连续；分类目标设置 `scroll-margin-top`。
- 所有输入、选择器、图标按钮和搜索控件必须有可访问名称、`name` 与适当 `autocomplete`。
- 键盘可完成：关键词搜索/清空、分类锚点、外链、F202a/F202b 触发、diff 接受/忽略/编辑、迁移策略、应用确认、CRUD 和条目分类。
- 对比度目标：正文至少 WCAG AA `4.5:1`，大字/图形至少 `3:1`；状态不只依赖颜色。
- 支持 `prefers-reduced-motion`、`prefers-reduced-transparency`、`prefers-contrast: more`；不禁用浏览器缩放。
