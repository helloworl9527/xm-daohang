# 收藏系统 UI 规范 v0.4（方向 C + Apple 对照，已确认界面）

> 状态：已确认界面。用户于 2026-08-08T20:25:30+08:00 原文确认“确认界面（方向C问答优先 + Apple交互增强，含提问框输入栏撑满调整）”；批准事实源见 `state.json.approvals.ui`。本文的方向 C、Apple 增强与输入栏几何均保持已确认版本。

## 1. 产品界面边界

- 同一 Next.js 应用分为公开展示端 `/` 与受保护管理端 `/admin`。
- 公开端：匿名、移动端优先，只展示每日稳定轮换的 3 条已完成收藏；底部正中固定提问框可公开检索全库；不提供全量浏览。
- 管理端：唯一站主使用用户名 + 密码登录，不启用 2FA；承载添加、全量库管理与全部配置。
- Telegram：仅约定消息交互与回执，不制作聊天应用仿真界面。
- 原型：`.workflow/ui-prototype/`；所有数据与成功回执只在浏览器内存模拟。

## 2. 选定设计方向

### 2.1 方向 C「问答优先」

- 设计主题：让公开访客先把收藏当成一个可提问的知识入口，再用每日 3 条进行轻量探索。
- 目标用户：以移动端访问为主的匿名访客；桌面与移动端的唯一站主。
- 页面唯一任务：公开端完成“立即提问或浏览 3 条”；管理端完成“收集、维护、配置”。
- 信息架构：居中品牌主张 → 回答/来源（提问后成为主内容）→ 3 条轻量索引 → 底部正中固定提问框。
- 核心流程：访客输入问题 → 限流校验 → 加载 → AI 归纳 + Top 10 来源 / 无结果 / 超限；默认态可打开 3 条每日收藏的原始链接。
- 色值：雾白 `#F5F7F4`、纯白 `#FFFFFF`、墨黑 `#17211D`、检索绿 `#087F6C`、来源蓝 `#265FAF`、信号珊瑚 `#D15A3C`。
- 字体角色：`Songti SC/STSong/Georgia` 用于公开标题、回答结论和条目名称；`Inter/PingFang SC` 用于正文与控件；`SFMono-Regular/Consolas` 用于日期、排名、额度和状态。
- 布局：公开端最大内容宽度 960px；桌面 3 列错落轻索引，移动端恢复自然单列；回答位于索引之前；管理端维持高密度左导航与列表/详情工作区。
- 标志性元素：固定提问框是公开端稳定锚点；`01/03` 为真实每日轮换顺序；3 条索引只用顶部线与错落节奏区分，不使用通用卡片墙。
- 组件状态：链接 default/hover/focus/pressed；提问框 default/focus/submitting/disabled；语言 active；管理条目 selected/processing/complete/failed；设置 default/saving/saved/error/disabled。
- 空/错/加载：结果与首页状态使用同一宽度和焦点路径；空库禁用提问；无结果与超限使用确认过的固定文案。
- 响应式：`<=820px` 取消索引错落、管理双列改单列；`<=480px` 提问按钮以图标显示但保留可访问名称。
- 无障碍：错落只改变桌面视觉位置，不改变 DOM 顺序；结果标题由 `aria-labelledby` 关联；固定提问框不自动抢焦点。
- 取舍：公开问答任务最突出；每日 3 条的视觉权重低于问答结果，与用户选择一致。

### 2.2 反模板化检查

- 不使用营销 hero、指标卡、渐变光球或装饰插画；首屏直接呈现“问整个收藏库”的任务与每日内容。
- 公开端不出现管理状态、处理失败、来源渠道、全量计数或配置字段。
- 管理端采用安静、密集的工作布局，不沿用公开端的大字号策展构图。
- Apple 增强不改成另一套 Apple 视觉语言，不新增圆角卡片、导航层级、底部 sheet 或手势流程。

## 3. Apple 交互增强

Apple 增强版严格保持方向 C 的信息架构、DOM 内容顺序、布局几何和 6 个核心色值不变，只增加以下行为：

1. **即时按压反馈**：按钮、链接式条目、来源、导航、设置标签在 pointer-down 即缩放至 `0.975`，释放后回到原位；不等待 click 才反馈。
2. **临界阻尼落位**：每日索引、答案、来源、状态、管理详情使用 `damping 1.0 / response 0.4s` 对应的 requestAnimationFrame 临界阻尼弹簧，从当前显示值落位，无弹跳。
3. **可中断动画**：移动中的元素收到 pointer-down 时立即取消当前帧并清除内联变换，用户无需等待动画完成。
4. **空间一致性**：答案与来源在原位置向上落位，管理详情在原详情区域落位；没有跨区域飞入或改变进入/退出路径。
5. **层级材质**：公开头部、管理侧栏、固定提问框和 toast 使用同色半透明材质、blur/saturation 与更明确阴影；不改变色相或布局尺寸。
6. **焦点抬升**：固定提问框 `:focus-within` 上移 4px、缩放 `1.008` 并增强同色焦点阴影，明确当前输入上下文。
7. **开关物理反馈**：开关圆点用带轻微回弹的曲线移动；不改变开关位置、标签或取值。
8. **多模态提交反馈**：浏览器支持时，在提问提交、登录成功、设置/编辑/重抓完成时使用 6–8ms 轻触觉；不播放声音，不对普通浏览触发。
9. **焦点可访问增强**：保留可见 outline，并增加检索绿的外层光环；不以阴影替代 outline。
10. **偏好适配**：`prefers-reduced-motion` 停止弹簧并把过渡缩短为近静态；`prefers-reduced-transparency` 改为纯色表面并关闭 blur；`prefers-contrast: more` 使用纯色表面与墨黑边框。

增强版没有拖拽、横向甩动、底部 sheet 或动量投掷，因为选定的信息架构没有需要直接操控的可移动对象；为展示效果新增这些手势会改变产品交互模型。

## 4. 总体信息架构

```text
公开展示端 /
├─ 每日轮换 3 条（仅完成状态）
│  └─ 标题 / 中文总结 / 标签 / 原始链接
├─ 固定提问框
│  ├─ AI 归纳回答
│  ├─ 命中来源 Top 10
│  ├─ 无结果 / 超限 / 错误
│  └─ 加载
├─ 空库
├─ 中 / 英语言
└─ 低权重站主入口 → /admin

管理端 /admin
├─ 登录（用户名 + 密码）
├─ 添加内容
├─ 收藏库全量管理
│  ├─ 关键词 + 标签筛选
│  └─ 详情 / 编辑总结 / 删除 / 手动重抓
└─ 设置
   ├─ 对话模型 / 嵌入模型
   ├─ 定时重抓
   ├─ 公开提问限流
   ├─ 安全（修改密码 / 会话）
   ├─ Telegram
   └─ 中 / 英语言
```

公开端绝不出现全量库入口、条目处理状态、失败原因、管理计数、API Key 或限流配置。未登录访问 `/admin` 页面或写接口必须被服务端拒绝。

## 5. 公开展示端页面与状态

### 5.1 首页每日轮换

- 默认：当日稳定展示 3 条已完成收藏；标题、2–4 句中文总结、3–5 标签和原链接。
- 加载：内容区骨架；品牌、语言和固定提问框位置不变；首次数据未就绪时提交禁用。
- 少于 3 条：展示实际数量，不补空卡、不报错。
- 空库：“收藏库还没有可展示内容”；只给站主登录入口；提问框禁用。
- 成功：同一天刷新保持同一组与顺序；次日更换不使用夸张动画。
- 失败：说明每日内容暂不可用并允许刷新，不暴露内部错误。
- 权限：无需登录；卡片只读；公开提问由服务端限流。

### 5.2 固定提问与结果

- 默认：底部正中固定；输入最大 500 字；显示“回答仅来自收藏库 · 最多 10 条来源”。
- 输入栏尺寸修订（用户 2026-08-08 指定）：左侧 label 与 input 必须撑满提问表单的可用左列，从容器左内边延伸到右侧提问按钮前；input 宽度等于 label 宽度，高度等于表单主行高度。桌面和移动使用同一规则，不出现浮在左侧的内在宽度小框；按钮位置不变。
- 加载：保留问题；结果区显示骨架和“正在检索收藏并生成回答…”；提交按钮禁用。
- 成功：先 AI 归纳，再显示最多 10 个命中；每项含排名、标题、总结、可点击原链接。
- 无结果：核心文案“收藏库中没有相关内容”；补充回答不会引用库外知识。
- 超限：核心文案“今日提问已达上限，请稍后再来”；明确本次不调用模型。
- 错误：保留原问题并提供重新尝试；不暴露模型供应商、Key 或堆栈。
- 禁用：空库或模型不可用时禁用提交，并用文本说明原因。
- 权限：公开匿名；前端额度只作友好反馈，服务端强制单 IP + 全站双重限流。

### 5.3 语言

- 顶部始终提供“中 / EN”；默认中文并本地持久化。
- 切换英文时界面文案切换；AI 总结与回答内容仍为中文。
- 缺失翻译回退中文，不出现空白键名。

## 6. 管理端页面与状态

### 6.1 登录

- 默认：用户名、密码、“登录管理端”；无 2FA、恢复码或注册入口。
- 加载：请求期间按钮“登录中…”并禁用。
- 失败：“用户名或密码不正确。失败次数已记录。”；不泄露账号是否存在。
- 锁定：显示剩余等待时间；字段与按钮禁用。
- 成功：建立会话并进入“添加内容”。
- 权限：会话超时回登录，受保护内容不得留在背景。

### 6.2 添加内容

- 默认：单 URL；说明只支持公开内容，并提示完成条目可能通过公开问答返回。
- 加载：按钮“添加中…”；保留输入；阻止重复提交。
- 成功：“已加入，正在抓取总结中”；库内新增“处理中”。
- 重复：“该链接已收藏”，提供进入条目与重抓，不新建记录。
- 失败：非法 URL 就近报错；服务失败保留输入。
- 禁用：任一模型未配置时阻断并引导模型设置。
- 权限：需会话 + CSRF；匿名请求重定向或 401/403。

### 6.3 收藏库与详情

- 默认：全量显示标题、链接、总结、标签、状态、来源、时间；关键词与标签组合筛选。
- 加载：列表骨架；详情不伪装为最新数据。
- 空库：引导添加；筛选无结果提供清除筛选。
- 完成：编辑总结、重抓、删除可用。
- 处理中：重抓禁用，避免重复排队。
- 失败：展示脱敏原因、自动重试耗尽和手动重抓。
- 编辑：成功后同步列表/详情并标“人工编辑”；失败保留草稿。
- 重抓：触发即转“处理中”；完成/失败通过状态和 `aria-live` 通知。
- 删除：二次确认；明确同时移除向量与公开检索来源；失败保留条目。

### 6.4 设置

- 模型：对话/嵌入两组独立 Base URL、API Key、模型名；Key 掩码；测试失败不覆盖现有配置；更换嵌入模型提示可能需重建向量。
- 定时重抓：开关、间隔天数、上次/下次时间；关闭时天数禁用。
- 公开限流：开关、单 IP 每日、全站每日；默认 `20/200`；显示当日已用；TG 不受此限。
- 安全：当前密码、新密码、当前会话、退出；无 2FA 控件。
- Telegram：Token 掩码、用户 ID 白名单；非白名单不响应。
- 语言：中文 / English；两端偏好一致；AI 内容固定中文。
- 通用：每组覆盖 default/saving/saved/error/disabled/permission；敏感值不进入日志或前端持久缓存。

## 7. Telegram 消息约定

| 场景 | 回执文案 |
| --- | --- |
| 新链接接收 | `已加入，正在抓取总结中。` |
| 收藏完成 | `✅ 已收藏\n{标题}\n{一句话总结}\n{原链接}` |
| 已存在 | `该链接已收藏。回复 /refetch {短 ID} 可重新抓取更新。` |
| 非法链接 | `没有识别到有效链接。请发送公开网页、文档或 GitHub 仓库链接。` |
| 最终失败 | `抓取失败：{脱敏原因}。回复 /retry {短 ID} 可重试。` |
| 提问处理中 | `正在检索收藏库…` |
| 有命中 | `{AI 归纳}\n\n来源（最多 10 条）：\n1. {标题} {链接}` |
| 无命中 | `收藏库中没有相关内容。` |
| 非白名单 | 不响应，不泄露库内信息。 |

Telegram 白名单提问不受公开端限流；可识别 URL 视为添加，否则视为提问。

## 8. 响应式规则

- 公开端从 390px 设计，支持最小 320px；管理端桌面优先但移动端可完整操作。
- `>=821px`：公开端 3 列错落；管理端 224px 左栏；收藏库列表/详情双列。
- `481–820px`：公开索引单列；管理侧栏转顶部图标导航；双列改单列；设置分类横向滚动。
- `<=480px`：提问按钮改图标并保留 `aria-label`；筛选和 URL 提交单列；详情操作换行。
- 正式提问框使用 `bottom: max(12px, env(safe-area-inset-bottom))`；原型因对照控制条暂上移 76px。
- 页面底部为固定栏预留空间；正式实现需验证 iOS Safari 键盘下的 Visual Viewport 或非固定退化策略。
- 长标题、URL、英文长词允许换行或截断；不以视口宽度缩放字号。

## 9. 无障碍约束

- 跳到主要内容；语义化 `header/nav/main/section/form/dialog`；标题层级连续。
- 键盘可完成全部流程；视觉与焦点顺序一致；明显 `:focus-visible`。
- 表单有可点击标签与正确 `type/name/autocomplete/inputmode`；不阻止粘贴；错误就近显示。
- 异步结果和 toast 使用 `aria-live="polite"`；锁定使用 `role="alert"`。
- 装饰图标 `aria-hidden`；纯图标按钮有 `aria-label`；状态不只依赖颜色。
- 触控目标至少 44×44px；正文与控件达到 AA 对比度；支持浏览器缩放。
- 删除使用 `dialog`；正式实现需焦点圈定与关闭后焦点返回。
- Apple 增强遵守 3 个用户偏好媒体查询，减弱动效时仍保留颜色/透明度等非运动反馈。

## 10. 原型偏差

- 静态内存数据，刷新重置；每日轮换未按日期真实选取。
- 登录预填凭证即可进入；输入 `wrong` 演示失败；锁定通过状态切换。
- 提问“火星/天气”演示无结果，“上限/limit”演示超限，其余演示命中；不调用模型。
- 额度 `12/20` 与全站 `86/200` 为明确原型数据。
- 英文只示范主要文案和偏好反馈，正式实现需完整覆盖两端。
- 对照控制条不属于产品；正式产品提问框贴近安全区底部。
- 使用 CDN Lucide；正式 Next.js 应本地打包图标。
- 筛选、结果和详情未完整深链；不得将 IP 或问题原文写入 URL。
- Vibration API 在不支持的浏览器静默跳过；它不是完成操作的唯一反馈。
